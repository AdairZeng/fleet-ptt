# fleet-ptt

面向司机和车队的语音优先群组对讲系统，产品角色名为 **小路**。设备不需要预先归属车队，开机进入公共频道；用户通过自然语音查询在线联系人、建频道并定向邀请、切频道、开始和结束对讲；浏览器中的 3D 对讲机用于验证未来硬件的操作、状态与音频体验。

## 配置

仓库仅提供 [`.env.example`](.env.example)。本地复制为 `.env` 后填写真实值，勿提交 `.env`。

灵矽智能体负责语音识别、语义理解、参数追问和语音播报，通过云端 MCP 调用 fleet-ptt 的频道、对讲和设备工具。MCP 使用 Streamable HTTP，地址为 `{PUBLIC_BASE_URL}/api/v1/mcp`，在灵矽私有自定义 MCP 中配置请求头 `Authorization: Bearer <LINX_MCP_TOKEN>`，并把 MCP 关联到“小路”智能体。配置步骤见 [灵矽接入方案](docs/linx-access.md)。

3D 原型和真实硬件使用统一设备协议。模拟设备注册时自动生成 `device_id`、`mac_id` 和 `device_credential`；真实硬件使用预配的同名字段。按下电源键后，服务端按该设备的 `mac_id` 检查并自动完成灵矽绑定，随后完成昵称设置、自动进入公共频道并收听。开机不自动发送对讲音频，按住 PTT 或说“你好小路，开始对讲”后才发送。指令音频通过 `/api/v1/linx/ws` 桥接到灵矽，普通对讲音频走七牛 RTN。

开机、完成昵称设置并允许麦克风后，前台页面持续通过灵矽识别语音。说“你好小路，创建一个装货频道”即可发起指令；服务端在识别到唤醒词并收到设备停止对讲的回执后开放业务工具与播报，指令键也可手动唤醒。播报完成后保留 20 秒补充或确认窗口，超时需重新唤醒；成功开始对讲后直接回到唤醒待命，避免把普通对讲话语当作后续指令。首次昵称设置仍使用文本输入。

云端唤醒使用灵矽 STT，不需要本地唤醒模型。待命和对讲期间的麦克风音频也会上传识别，可能消耗灵矽额度；对讲中收到整句 STT 之前，整句唤醒和指令都可能已传给频道。TTS 期间暂停上传，实际播放结束后恢复；页面隐藏时暂停，返回前台恢复。

说“你好小路，邀请老王加入装货频道”，服务端会复用自己已加入的同名频道或创建频道，让发起者切入并向在线的老王发送邀请。邀请不要求双方在同一频道；老王接受后才加入并切换，拒绝则留在原频道。邀请两分钟有效，离线不排队；同名联系人先澄清。说“你好小路，谁在线”可以查询联系人，说“你好小路，回到公共频道”可以回到默认频道。

完整本地联调需要公网隧道暴露 MCP 的 Streamable HTTP 端点，并配置真实灵矽和 RTN 凭证。真实灵矽音频、工具调用、唤醒声学效果和双端对讲尚未完成联合验收，验收步骤见 [验收记录](docs/acceptance.md)。

## 本地启动

```bash
cp .env.example .env
make up
```

`make up` 会执行 `docker compose up --build`，浏览器访问 <http://localhost:8080>。`make health` 检查进程探活，`make down` 停止并移除容器。数据目录 `data/` 挂载到容器 `/data`。

开发时可以分别运行：

```bash
make server
make web
```

`make web` 将 `/healthz`、`/api` 及 WebSocket 代理到 Go 服务。`make server` 默认从 `web/dist` 托管静态资源，并使用 `data/fleet-ptt.db` 作为本地数据库路径；运行会话功能前需设置 `SESSION_SECRET`。
